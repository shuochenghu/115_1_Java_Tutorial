# 第 11 週作業｜取回樣本最多的原來源

先完成課堂四個 TODO 與 AI 最小修正。課後必做估計 25–35 分鐘，規模是一個方法及一個驗證 main，不另做第二套系統。

## 必做功能

在自己的 `SampleGroup<T extends SampleSource>` 新增 `public T findMostSamples()`：回傳目前樣本數最大的**原物件**，平手保留最先加入者。呼叫前須先確認 `size() > 0`，本週不要求空群組的例外處理。查詢不改來源能源、樣本、行動／鑽探次數，也不建立一個替代物件。

方法宣告與測試啟動框架如下，搜尋最大值的迴圈由你自己寫。框架要在方法完成後才放正式 src；檔名使用 `MostSamplesDemo.java`。

```java
public class MostSamplesDemo {
    public static void main(String[] args) {
        SampleGroup<SampleTray> trays = new SampleGroup<>();
        // 自行建立三筆以上資料，包含中間最大與不同物件的平手。
        // add 完資料後，先確認非空，再呼叫 findMostSamples。
        // 印樣本數，並用 == 驗證是否為預期的原物件。
    }
}
```

## 最低驗收固定，資料與展示可自訂

| 案例 | 必須證明 |
|---|---|
| 三筆以上樣本盒，例如 4、9、9 | 最大值在中間出現、末筆平手時仍回第一個 9；用物件參考比較，不只比數字 |
| 重型車群組，至少兩台不同狀態 | 回傳可直接指派給 HeavyRover 並查能源，不寫轉型；查詢後來源狀態不變 |
| 單筆 0 份來源 | 回傳那個 0 份原物件，不誤判為無資料 |
| 空群組 | size 與 totalSamples 為 0，先判斷再略過最大值查詢 |
| 回傳型態的獨立編譯反例：`SampleGroup<SampleSource>` 的 `findMostSamples()` 結果直接指派給 `SampleTray` | 說明為何這行應被拒絕（回傳型態跟著群組的 T），實際保存診斷，不混入正式 src |

車輛可直接以合法建構值作固定資料，例如 `new HeavyRover(18, 4)`，不必再執行任務。資料、標籤與展示方式可自行安排，但要寫出每個案例能抓什麼錯誤。完成後重跑課堂九行，不能為了作業破壞既有功能。

選做擇一：實作教師示範的泛型方法，或研究 `? extends SampleSource` 作為查詢參數的限制。選做不列下週共同先備，不要求兩種都寫。萬用字元不代表集合或物件不可變。
