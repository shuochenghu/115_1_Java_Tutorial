# 驗證與交付

## 先界定驗證目的

先說清楚誰操作、驗證什麼、用什麼證據判定、失敗如何診斷。教師工具、作者執行與學生本人測試分開；只做文件修訂時，檢查受影響的內容與連結即可，不強迫執行無關 Java。

## 程式

1. 記錄 `java -version` 與 `javac -version`。使用新的暫存輸出目錄，分開編譯 examples、starter、teacher；只在編譯成功後執行對應 classpath。可用 `javac -encoding UTF-8 -Xlint:all -d <輸出目錄> <本次來源檔案>`，依實際相依關係列檔。
2. starter 的目標是能啟動、安全返回、保留指定 TODO；teacher 才驗收完整功能。完成的學生程式若搭配教師檢查工具，只編譯這份完成碼，不同時加入 teacher 的同名類別。
3. 由需求預先計算期望結果，再比對實際輸出；涵蓋正常路線、恰好足夠、能源不足、充電上限、返回、無效指令、初始已停止、空資料及成功優先等本次相關案例。區分「成功行動數」與「讀入指令數」。
4. 互動程式以有結束路徑的輸入及合理逾時執行；無法結束要定位停止條件，不留背景程序。尚未教授的完整例外處理不列入學生必做驗收。
5. AI 錯誤示範在副本重現，記錄修改前的失敗、最小修正與重測；正式教師答案維持正確。早期週次採簡單教師檢查工具，不要求學生先學 JUnit。

不要以舊 out 目錄、只看 exit code、只看輸出片段、教師斷言或 AI 說明取代實際結果。--release 設定不證明已在該版本 JVM 執行。

## 文件與教材對齊

- 核對規則、初始值、輸入序列、輸出、題號、TODO、必做與延伸、檔名／public class、工作目錄及執行指令。
- 學生講義保留作答空間，教師筆記逐題有答案及診斷；作業有可觀察的驗收與完整繳交清單。
- AI 範本有少量欄位及清楚標示的虛構示範；不讓示範內容看起來是學生或作者已實測。
- 檢查 Markdown 本機連結及 code fence；以 UTF-8 讀寫中文路徑。執行 `git diff --check`，新增未追蹤檔另檢查，因為一般 diff 不涵蓋它們。
- 不交付 .class、臨時輸出或測試用錯誤副本。只清除本次建立且已確認位置的暫存檔，不刪他人的產物。

## Marp 投影片

依目標版本既有 16:9、中文字型、配色及講者備註延續；重點是可投影閱讀、程式碼不截斷、學生知道要開哪個檔案及做哪個活動，不固定頁數。

修改 Markdown 後同步該任務要求的 HTML／PDF 等匯出物。記錄實際匯出工具版本。以可用的瀏覽器或渲染工具檢查頁數一致、文字／表格／程式碼溢出與重疊；縮圖巡視、代表頁放大與逐頁放大檢查須據實區分。單純檔案存在、匯出成功或程式偵測未溢出，都不能單獨稱為完整視覺驗收。

## 驗證紀錄與交接

在當週 verification 或等效文件記錄日期、環境、命令／方法、案例、期望與實際結果，以及未完成項目。依實際執行情況區分：

| 證據 | 能支持的結論 |
|---|---|
| 靜態核對 | 路徑、文字、規則與檔案結構符合檢查範圍 |
| CLI 編譯與執行 | 該 JDK、輸入與原始碼的實際行為 |
| HTML 匯出／視覺檢查 | 已檢查的匯出與頁面版面 |
| 本機模擬 Git remote | 本機版本控制流程，不能推論遠端登入成功 |
| 真實 GitHub／AI 服務 | 實際帳號、環境及時間下完成的操作 |
| VS Code／IntelliJ GUI | 該 IDE 的設定及執行路徑 |
| 學生試教 | 實際課堂的時間、理解與操作觀察 |

handoff 記錄已覆蓋能力、尚需診斷的能力、下一週動機及資料契約。若已有 PROJECT_MEMORY.md，同步長期決策、變更檔案、驗證範圍、尚未完成項目及實際分支／提交狀態。沒有成功 fetch 及比對前，不宣稱本機已與遠端同步；沒有提交就明說尚未提交。
