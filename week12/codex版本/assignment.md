# 第 12 週作業｜每筆處理與批次摘要

必做約 25～35 分鐘，使用自己的額度完成版；不需要第 11 週成果。保留原檔版本紀錄，再改 `src/PrintQuotaDemo.java`。執行緒以課堂 B1、B2 成果繳交，不再新增共用資料題。

## 要修改什麼

抽出 `public static boolean processOne(PrintQuota quota, String raw)`，在其中完成一筆轉換、申請、兩個 catch 與一行結果顯示。成功受理回 true，兩類拒絕都回 false。main 的迴圈呼叫這個方法一次，依結果累計受理、拒絕筆數，最後印摘要。不要在 main 再次呼叫 reserve；不要用 finally 計算成功數。

額度物件與 raw 約定非 null。其他契約與課堂相同：新物件 10 頁、每筆 1～5 頁、先檢查範圍再檢查額度、拒絕不扣、下一筆繼續、trim 後解析。不改 PrintQuota 的規則或固定訊息。

## 要跑什麼、應該看到什麼

沿用 README 的編譯方式與 PrintQuotaDemo 入口。固定六筆仍印相同的六行逐筆結果，最後一行改成：

```text
批次結束 受理=3 拒絕=3 剩餘=0
```

驗收至少四組，每組重新建立額度物件：

| 資料 | 預期 |
|---|---|
| 原固定 3、abc、0、5、4、2 | 受理 3、拒絕 3、剩餘 0；每筆只計一次 |
| 自選混合資料 | 同時有格式拒絕、規則拒絕、正常資料，且拒絕後至少有一筆成功；先算再跑 |
| 5、5、1 | 受理 2、拒絕 1、剩餘 0；最後一筆拒絕不再扣 |
| 空陣列 `String[] inputs = {};` | 不印逐筆結果，只印受理 0、拒絕 0、剩餘 10 |

判讀結果時，同時檢查「受理＋拒絕＝讀入筆數」與額度。總筆數正確仍可能扣錯；額度正確也可能把拒絕計成受理。自選資料、預期、實際與差異理由附在 LAB_REPORT.md，測完恢復固定六筆作為繳交預設。
