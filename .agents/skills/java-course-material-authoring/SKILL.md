# Java 教材製作共用技能

本技能供 Codex 與 Claude Code 共用，規範正文只維護於此。所有專案路徑以儲存庫根目錄為基準；支援文件的連結以本檔所在目錄為基準。使用繁體中文，程式識別字依 Java 慣例。

## 開始工作與範圍

1. 先看工作區狀態及適用的 AGENTS.md／CLAUDE.md；若有 PROJECT_MEMORY.md，讀取與任務有關的決策。保留使用者及其他作者未完成的修改。
2. 讀取根目錄 `物件導向程式設計與AI協作_課程大綱_整合版.md`，再讀目標週、前一週的 README、學生講義、教師程式及 handoff；若有後續週，核對其實際使用的先備能力。首次處理本課程或涉及跨週變更時，讀 [課程脈絡與交接](references/course-context.md)。
3. 先確定目標週、版本目錄、交付項目、先備能力、本週新增能力、下一週入口及輸入／狀態規則。可由現有文件判斷的事項直接處理；只詢問會實質影響成果的缺漏。
4. 依使用者指定範圍工作。局部修訂只同步受影響的教材；審查請求先回報具體問題與證據，不自動重寫整週。製作請求應完成可使用的成果。

## 學生與教學設計

- 對象為已有基礎 C# WinForms 經驗的資管系二年級學生。以 C# 事件處理 → Java main → 方法、參數、回傳值及除錯銜接；用短診斷題補強，不從零重教所有程式基礎。
- 知識點依「概念、為何需要、程式位置、操作順序、預期結果、失敗診斷、適用限制」說清楚。課堂活動採概念 → 示範 → 引導 → 獨立實作 → 檢查 → 反思，讓學生先預測再執行。
- 每個主要範例集中新增一項核心負擔。範例要有實際情境及可比較的選擇，避免只有換字輸出的單調練習；故事的豐富度不能靠未教技術堆出來。
- 規畫、製作及審查教材時，評估學生練習與作業是否足以支持本週學習目標，份量適中。保留從引導到獨立實作、驗證與修正的機會，不讓教師示範或完整支援碼代做核心學習；依先備能力、課堂時間及課後負擔區分必做與選做，避免重複抄寫或只換數字的練習。不固定每週題數、TODO 數或遷移題數。
- 「骨架曾出現」不等於已教會：main 的 String[] args 不代表學生已學陣列，使用 Scanner 不代表會設計類別。支援碼要說明角色，與學生必寫能力分開。
- 工具教學依程式規模安排：單一程式以 VS Code 為主；專案超過兩個程式檔（至少三個）時再加入 IntelliJ IDEA。兩檔基本範例仍可沿用 VS Code，不要求每個活動都在兩套 IDE 重做。多檔時解釋來源根目錄、相依類別與 main 入口，再示範 IDEA 專案操作。
- 沿用三節各 50 分鐘、休息另計的備課配置；這是現有教材慣例，不是課綱規定或已完成試教的證據。保留操作、除錯、討論及最後約 15 分鐘保存成果；清楚區分必做與延伸。
- 沿用火星探測車主線時，從前週尚未解決的問題引出本週概念。可用短篇替代情境增加變化，但不要另建一套大型系統。

## 原稿、版本與成套交付

- 教材的製作、修改、修正、同步及重新匯出依工具分版處理：Codex 只處理 `weekNN/codex版本/`，Claude Code 只處理 `weekNN/claude版本/`。未指定版本的「檢視並修改第N週」也只修改執行工具自己的版本；另一版本可作參考，不連帶修改其程式、文件、投影片或驗證紀錄。共用規範（本技能及 references）仍可依任務同步。此規則自2026-10-15使用者補充後適用，不自動回復先前已完成的跨版本修改。
- 原始教材、週根目錄共用文件及另一模型版本保留不動。新教材由 Codex 製作放 `weekNN/codex版本/`，Claude Code 製作放 `weekNN/claude版本/`；不因參考另一版而搬移或改寫其檔案。只有使用者在當次請求明確指定跨版本修改、覆寫或整合時才例外。
- Claude Code 製作的教材必須能從資料夾與檔名直接分辨為 Claude 版：
  - 資料夾：放在 `weekNN/claude版本/`（含 `code/` 等子目錄），不寫入 `codex版本/` 或週根目錄。
  - 檔名：Claude 新建的非 Java 檔案一律加 `_claude` 後綴，匯出物與原稿同名，例如 `README_claude.md`、`weekNN_slides_claude.md`／`.html`、`weekNN_實作講義_claude.md`、`weekNN_教師筆記_claude.md`、`weekNN_作業說明_claude.md`、`weekNN_驗證紀錄_claude.md`、`AI使用紀錄表_範本_claude.md`。
  - 內容標示：文件標題註明「（claude 版本）」，開頭說明初稿由 Anthropic Claude（Claude Code）生成；README 另說明兩版獨立製作及 Codex 版位置。Marp 投影片每頁加 `by-claude` class，顯示 claude 徽章。
  - Java 原始檔：檔名須等於 public class，維持原名，以 `claude版本/` 目錄區分，並在檔頭註解標明「claude 版本」。
  - 修改既有 Claude 版時沿用其原有檔名；week01 等早期未加後綴的檔案不追溯改名，除非使用者要求。
- 參考另一版本時取用可核對的設計，重新驗證程式與答案，不把其正確性視為既定事實。Java 檔名須與 public class 相符，不為模型署名改壞類別名稱。
- 製作完整一週時，沿用目標版本既有命名與結構，提供下列功能；已有等效文件不重複新增：

| 成果 | 必須解決的問題 |
|---|---|
| README | 目標、先備能力、檔案索引、操作位置、執行與限制 |
| Marp 投影片及要求的匯出檔 | 講授脈絡、示範、活動入口與講者備註 |
| 學生實作講義 | 可填的預測、追蹤、實測、錯誤修正及反思 |
| 作業說明 | 必做／延伸、輸入契約、案例、繳交與驗收標準 |
| examples 與 starter | 獨立可執行範例、合理的 TODO 骨架 |
| teacher 與教師筆記 | 完整解答、預期結果、教學節奏、誤解與診斷 |
| AI 使用紀錄範本 | 少量欄位、清楚標示虛構／模擬的完整填寫範例 |
| handoff 與 verification | 下一週能力契約、實測範圍及尚未驗證項目 |

- 學生 TODO、講義題號、教師答案、作業規則及投影片的程式檔案對照必須一致。starter 預設可編譯並安全結束，但不能宣稱佔位結果已滿足功能；刻意設計編譯錯誤的練習另標示。
- 不把教師答案塞進學生 TODO。starter 與 teacher 可能有同名類別，分開編譯及輸出目錄；不得把兩份同名類別一起放入學生 src。

## Java 與規則正確性

- JDK 不限定特定版本。使用符合當週範圍的普通、非預覽 Java；記錄實際 java／javac 版本。若某 API 有最低版本需求，查核並說明。保留舊教材的歷史版本紀錄，不回寫成新的實測結果。
- 第3至5週及後續教材的預設編譯指令不加入固定版本的 --release、-source、-target，也不在 IDE 設定鎖定特定 SDK。只有使用者另行指定相容性目標時才加入對應設定，並分開記錄編譯目標與實際執行版本。
- 註解說明目的、狀態規則、停止條件與不直觀的選擇；不逐行翻譯已教語法。先用具名狀態及已教控制流程，再引入下一階段的抽象化。
- 互動活動要有清楚的結束路徑，腳本活動要定義讀取與停止時機。先定義輸入範圍；未教例外處理時可限制合法整數，不暗中擴張成完整輸入防護作業。
- 同步核對正常、邊界、被拒絕與停止案例；狀態初始已完成、零能源、空資料、同時觸發多個終止條件時尤其容易出錯。只測合法輸入契約內的案例；契約外行為另記限制。

## AI、版本控制與來源

- AI 活動應有需求描述、學生預測、建議判讀、反例重現、最小修正及重測。保留人工初版與採納／拒絕理由；AI 宣稱正確不能代替編譯執行。
- AI 紀錄保持精簡，沿用當週欄位，不強迫所有週改成同一欄數。模擬錯誤、虛構填寫示範、教師示範、學生本人驗證與真實 AI 對話要區分；未使用 AI 仍須記錄課堂程式驗證。
- 學生沿用 `115_1_Java/YYYY_MM_DD/java-NN/src/`，日期以實際上課日替換；LAB_REPORT.md、AI_USAGE.md 依當週指引放置。GitHub Desktop 為主要教學介面，CLI 為補充；不在日期或專案內再建巢狀 repo。
- 保存流程涵蓋檢查差異、commit、push、遠端核對及重新取回後編譯；本機模擬 remote 與真實 GitHub 操作分開記錄。編譯輸出及憑證不放進學生提交檔案。
- 教科書依本專案 Deitel《Java How to Program, Early Objects》11e EPUB 的實際章節引用，不猜紙本頁碼、不複製全文。Java／IDE／GitHub／AI 工具的易變行為查官方文件；無法查證時標示待核對，不杜撰來源。

## 驗證與交付

依本次變更選擇必要驗證，文件小改不強迫重跑所有程式。詳細方法見 [驗證與交付](references/validation.md)。

- 程式修改：記錄環境，乾淨目錄分開編譯 examples、starter、teacher，驗證與本次規則相關的輸入及完整輸出。早期週次用教師工具即可，不把 JUnit 提前變成學生要求。
- 教材同步：確認題目、TODO、完整答案、預期輸出、路徑、連結、繳交與驗收一致。
- 投影片修改：同步要求的 HTML 等匯出物，檢查實際版面；成功匯出不等於完成視覺檢查。
- 清楚分列靜態檢查、CLI 執行、視覺檢查、本機模擬、真實遠端／服務、雙 IDE GUI 與學生試教。只有實際做過的才能寫成通過，歷史結果不得冒充本次驗證。
- 交付時報告改動、主要設計理由、實際驗證與限制。若專案已有 PROJECT_MEMORY.md，更新本次長期決策、改動與交接資訊；未有此檔時沿用該週 handoff／verification，不為套格式另建記憶檔。不修改工具的使用者層級記憶，除非使用者明確要求。

## 共用方式

Codex 的專案入口為本目錄；Claude Code 的 `.claude/skills/java-course-material-authoring/SKILL.md` 只導向本檔。根目錄 AGENTS.md 與 CLAUDE.md 提供教材任務的讀取指引。維護規範時改本檔及 references；只有名稱、觸發描述或位置變動時才同步調整入口。

可明確指定：Codex 使用 `$java-course-material-authoring`；Claude Code 使用 `/java-course-material-authoring`，後接週次及工作要求。若目前工作階段尚未發現新技能，直接要求讀取本檔即可。

入口位置依據：[Codex skills](https://developers.openai.com/codex/skills/)、[Claude Code skills](https://code.claude.com/docs/en/skills)。此配置適用可讀取本儲存庫的 Codex／Claude Code；不代表已安裝到 Claude 網頁版或帳號層級。
