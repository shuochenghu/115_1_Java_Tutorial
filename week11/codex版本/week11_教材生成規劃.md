# 第 11 週教材生成規劃（Codex 版本）

規劃日期：2026-11-19。課綱主題為「泛型（Generics）與型別安全設計：AI 協作學習 Java 進階特性」，課綱週期為 11/22–11/28。承接第 10 週 Codex 版的 `SampleSource`、探測車與樣本報表，規劃三節各 50 分鐘，休息另計。課堂與作業時間均為備課估計，尚未試教。

本次交付為教材生成規劃。以下的檔案、TODO、投影片及驗收表是後續製作規格；本週完整教材尚未生成。既有各週與其他作者的版本保留。

## 一、教學主張與學習目標

學生已經會使用 `ArrayList<MissionStep>`。本週把問題推進一步：「為什麼放進去時能檢查型態，取出來時也知道它是什麼？自己設計的類別能否保有這項能力？」

主線採地面站的「樣本來源群組」。同一份群組程式可以管理樣本盒、重型車，或混合來源；每一個群組宣告自己接受的元素型態，並計算目前總樣本數。群組除了保存資料，還有樣本統計的領域責任，讓學生有理由使用自訂泛型類別。

完成本週核心活動後，學生應能：

1. 區分 `class Box<T>` 中的型態參數、`Box<String>` 中的型態引數，以及一般方法傳入的值。能說明泛型類別中的實例方法 `T get(...)` 與自行宣告 `<T>` 的泛型方法有何不同。
2. 宣告並實作 `SampleGroup<T extends SampleSource>`，以 `ArrayList<T>` 保存資料，讓 `add(T)`、`get(int)` 維持同一個元素型態。
3. 說明型態上限為何讓方法能呼叫 `getSamples()`；此處 `extends` 也可指定介面，不寫成 `<T implements SampleSource>`。
4. 依群組的宣告型態預測存入、取出及賦值是否通過編譯，並以實際診斷支持判斷。
5. 辨識 AI 建議中的未檢查轉型，重現「編譯有警告、取出時才失敗」，以保留型態資訊的最小修改恢復檢查。

第 2、3 項是學生實作重點。泛型方法安排教師短示範及閱讀題，萬用字元安排延伸，不把所有泛型語法都列成必寫作業。

## 三、實作方法盤點與取捨

| 方法 | 能解決的問題／代價 | 課堂定位 |
|---|---|---|
| 直接用 `ArrayList<SampleSource>` 加上普通統計方法 | 最少程式即可混合管理車輛與樣本盒；取出時只保證有介面操作 | 開場基準、教師設計對照。單純混合統計時，這已是合理做法 |
| 為車輛、樣本盒各寫一份群組 | 取出型態清楚，但儲存與遍歷邏輯重複，修正時可能漏改其中一份 | 短片段比較動機，不要求學生抄寫兩套 |
| `Object` 容器或 raw type，加上轉型 | 放入容易，取出需要額外判斷，容易把錯誤留到執行時 | 教師反例。區分 `ArrayList<Object>` 與省略型態引數的 raw `ArrayList`；兩者不是同一種宣告 |
| `SampleGroup<T extends SampleSource>` | 保留每個群組的元素型態，又能共用樣本統計；需要理解型態參數與上限 | 課堂主線，學生親自完成 |
| 泛型方法 `<T extends SampleSource> T moreSamples(T left, T right)` | 一次呼叫比較兩個來源並回傳其中一個；同為樣本盒的引數可直接回傳為 `SampleTray` | 教師 5 分鐘短示範與閱讀題，不列主線 TODO |
| `ArrayList<? extends SampleSource>` 的唯讀統計入口 | 可讀取多種具體元素型態的清單；新增非 null 元素受到限制，另需理解萬用字元 | 教師備查／學生選做，不列下一週共同先備 |

選擇主線的理由是需要同時示範「可重用的領域操作」與「取出時保留具體型態」。若需求只有混合來源的總和，應能選擇簡單的介面清單，不把自訂泛型說成所有集合需求的必要做法。

刻意省略自製泛型介面、多重型態上限、`Comparable<T>` 排序、PECS 完整規則、泛型陣列、反射與橋接方法。型態擦除只留教師備查，另用一個第 10 週延伸題說明不能只靠 `ArrayList<HeavyRover>`／`ArrayList<SampleTray>` 建立兩個同名單參數過載；不要求學生背編譯器轉換細節。

## 四、範例與主線程式契約

### 1. 短例先說明「T 換成誰」

`examples/TypedBoxDemo.java` 搭配簡短的 `Box<T>`，只示範建構時保存一個值、取出時回傳 `T`。以 `Box<String>` 與 `Box<Integer>` 各使用一次；先預測取出的型態，再執行。以 C# `List<int>` 的經驗提醒 Java 使用 `Integer` 作為型態引數，裝箱只做足夠讀懂範例的說明，不擴張為數值運算課。

短例的無上限 `T` 負責「存入與取出」；進入樣本統計時再問：「編譯器還不知道 T 有 `getSamples()`，應如何描述需要的能力？」以需求引入上限。

### 2. 核心類別與操作

| 宣告／方法 | 契約 | 學生工作 |
|---|---|---|
| `class SampleGroup<T extends SampleSource>` | 每個群組指定一個元素型態；T 必須符合樣本來源介面 | TODO 1：補型態參數、上限、private `ArrayList<T>` 與建構初始化 |
| `void add(T source)` | 存入有效且非 null 的來源；保留加入順序，允許重複加入 | TODO 2：使用 T 宣告參數並保存參考，不轉型、不操作來源 |
| `T get(int index)`、`int size()` | 回傳原本存入的物件參考與筆數；合法索引為 `0 <= index < size()` | TODO 3：實作查詢，呼叫端示範不需顯式轉型 |
| `int totalSamples()` | 普通迴圈讀取各來源當下的樣本數並加總；空群組為 0 | TODO 4：為原本的 T 加上 `extends SampleSource`，再自行寫累計，不回傳筆數、不寫死數量 |

starter 先提供可編譯的 `class SampleGroup<T>` 及方法簽名；TODO 1–3 練習型態一致的儲存與取出。到 TODO 4 才先預測「T 尚未承諾有 getSamples」的編譯結果，再由學生補上上限。骨架方法的佔位回傳不是功能答案，展示入口在完成前只顯示「尚未完成」，不把 `get` 的 null 佔位值交給報表使用。

總量限制為 `int` 可表示的非負小整數；本週不處理溢位。重複加入同一來源代表兩筆資料，總和會計算兩次，必須在教材明說。

群組保存的是來源物件的參考，不是數量快照。來源之後若由別處合法更新，下一次統計會讀到新數量；群組自己的 `add`、`get`、`size`、`totalSamples` 不得改變車輛能源、樣本、成功行動數或任務日誌。建構後不能從公開 getter 直接取得內部 `ArrayList`。

### 3. 三種群組使用相同類別

| 宣告 | 可以存入／取出時知道的型態 | 可觀察結果 |
|---|---|---|
| `SampleGroup<SampleTray>` | 樣本盒；`get(0)` 回傳 `SampleTray` | 4 份與空盒合計 4 |
| `SampleGroup<HeavyRover>` | 重型車；`get(0)` 回傳 `HeavyRover`，可呼叫車輛 getter | 已執行任務的重型車有 6 份、能源 8；不需轉型即可查能源 |
| `SampleGroup<SampleSource>` | 可混合存入重型車與樣本盒；取出只保證為 `SampleSource` | 6、4、0 合計 10；交給共用報表時只有樣本數 |

正式入口 `SampleGroupDemo` 由教師提供車輛與資料建立流程。重型車從 `20/0` 執行一次 `{1, 1, 2}`，停於能源 8、樣本 6、成功行動數 2、日誌 2 步；每個任務使用新車且只執行一次。完成版入口須有可逐行比較的繁體中文輸出。

`SampleGroup<HeavyRover>` 不能直接賦值給 `SampleGroup<SampleSource>`。用反問說明：若允許，透過後者放入樣本盒後，原本的重型車群組如何保證取出的是重型車？合法的混合做法是從一開始建立 `SampleGroup<SampleSource>`。不以轉型繞過檢查。

## 六、AI 協作：不能用轉型假裝保留型態

學生先保存人工完成版，再用 3–5 句寫需求：群組接受哪些型態、取出須保留什麼型態、如何統計、哪些狀態不能改，以及空群組結果。先預測「重型車群組能否放入樣本盒」。

教師提供的模擬 AI 版保留泛型類別宣告，卻把方法改成：

```java
// 模擬 AI 錯誤：參數放寬後，再用未檢查轉型塞回清單。
public void add(SampleSource source) {
    items.add((T) source);
}
```

活動在 `ai-check/` 隔離副本進行，不覆蓋正式完成碼。執行順序固定：

1. 以正確資料跑通正常入口，觀察只測合法資料為何看不出問題。
2. 用 `javac -encoding UTF-8 -Xlint:unchecked` 編譯錯誤版與反例。`SampleGroup<HeavyRover>` 此時竟能接收 `new SampleTray(4)`，編譯器對 `(T)` 發出未檢查轉型警告。
3. 執行反例，將 `get(0)` 指派給 `HeavyRover` 時出現 `ClassCastException`。本週只辨識失敗時機及出錯行，不要求處理例外。
4. 把參數恢復為 `T`，直接加入 source，移除轉型。以同一份反例重新編譯，這次應在錯誤的 `add` 呼叫處被拒絕。這是修正成功的負向證據，不應再要求該反例成功執行。
5. 另跑原本的合法入口，確認正常資料、空群組、總和、取出型態及無副作用仍正確，且沒有未檢查警告。

紀錄限需求／預測、問題證據、最小修正、重測與採納理由。模擬回覆須明標為教師設計；若學生使用真實 AI，另外記工具及實際驗證。未使用真實 AI 仍可完成全部核心活動，不以「有問 AI」代替編譯與執行證據。

## 七、課後作業與評量

必做估計 25–35 分鐘：在自己完成的 `SampleGroup<T extends SampleSource>` 新增 `T findMostSamples()`，回傳樣本數最多的原物件；平手保留最先加入者。呼叫前必須確認 `size() > 0`；空群組只檢查筆數與總和，不呼叫此方法。第 12 週才可另討論以例外表達空資料需求。

學生自行設計合法資料與標籤，但驗收至少包含：

- 一個只含樣本盒的群組，資料不少於三筆，能同時抓出「只回第一筆」與「平手改回最後一筆」的錯誤，例如 4、9、9；以物件參考比較確認選到第一個 9。
- 一個重型車群組，取回最大來源後可直接查車輛 getter，不寫轉型；可用教師提供的合法固定狀態，無須再跑一套任務。
- 一筆樣本數為 0 的非空群組，以及空群組的呼叫前判斷。
- 一個放錯元素的獨立編譯反例，說明預期被拒絕的位置。

保留相同的最低要求，學生可改資料、類別子型態及展示方式。教師提供啟動框架與驗收規格，尋找最大來源的迴圈由學生完成。選做為實作教師短示範的泛型方法，或比較唯讀萬用字元入口；擇一即可，不要求兩條路都寫。

繳交完成的 `src/`、`LAB_REPORT.md`、`AI_USAGE.md`。負向編譯片段與證據放報告，不把故意無法編譯的 `.java` 混進正式 `src/`。

| 評量面向 | 比例 | 判定依據 |
|---|---|---|
| 泛型宣告與型態安全 | 30% | T、上限、add／get 一致；錯誤資料在編譯時被拒絕，無 raw type 與未檢查轉型 |
| 功能與資料規則 | 30% | 總和、最大來源、平手與零樣本正確；保留原物件且不改來源狀態 |
| 驗證與修正 | 25% | 有預期與實際、反例、AI 最小修正，以及修正後合法與非法案例的證據 |
| 解釋與保存 | 15% | 能說明 get 回傳型態及參考語意；有可取回編譯的程式與精簡紀錄 |

學生路徑沿用 `115_1_Java/YYYY_MM_DD/java-11/src/`，日期為實際上課日；`LAB_REPORT.md` 與 `AI_USAGE.md` 放 `YYYY_MM_DD/`。examples、starter、teacher、ai-check 同名類別分開編譯及輸出。以 GitHub Desktop 檢查差異、commit、push、遠端核對及 repo 外取回重編譯，排除 `.class`、out、錯誤副本與憑證，不建立巢狀 repo。

## 九、教材驗收與本次規劃驗證

以下是完整教材生成後必須達到的驗收，不代表本週已有正式交付程式。

| 案例 | 預期證據 |
|---|---|
| 樣本盒群組 4、0；混合群組 6、4、0 | 筆數／總和分別為 2／4、3／10；順序與取回物件一致 |

## 十、教科書與官方規則依據

已核對本專案 Deitel《Java How to Program, Early Objects》11e EPUB 的目錄：第 20 章 **Generic Classes and Methods: A Deeper Look**；主線參考 §20.6 Generic Classes，泛型方法閱讀參考 §20.2–20.4，教師延伸參考 §20.5 Overloading Generic Methods 與 §20.7 Wildcards in Methods That Accept Type Parameters。裝箱補充對應 §16.3 Type-Wrapper Classes、§16.4 Autoboxing and Auto-Unboxing。這是本週教學順序的取捨，並非逐節照抄教科書；不猜紙本頁碼。

官方規則於 2026-11-19 查核：

- [JLS §4.4 型態變數與上限、§4.5 參數化型態](https://docs.oracle.com/javase/specs/jls/se25/html/jls-4.html#jls-4.4)、[§8.1.2 泛型類別](https://docs.oracle.com/javase/specs/jls/se25/html/jls-8.html#jls-8.1.2)：泛型宣告及型態引數規則的依據。
- [Oracle：Bounded Type Parameters](https://docs.oracle.com/javase/tutorial/java/generics/bounded.html)：上限可提供可呼叫的操作；介面上限也使用 extends。
- [Oracle：Generics, Inheritance, and Subtypes](https://docs.oracle.com/javase/tutorial/java/generics/inheritance.html)：元素之間的繼承關係，不會自動變成不同型態引數容器間的繼承關係。
- [Oracle：Generic Methods](https://docs.oracle.com/javase/tutorial/java/generics/methods.html)：方法自己的型態參數寫在回傳型態之前，可由呼叫推斷型態。
- [Oracle：Raw Types](https://docs.oracle.com/javase/tutorial/java/generics/rawTypes.html)、[Restrictions on Generics](https://docs.oracle.com/javase/tutorial/java/generics/restrictions.html)：raw type 的檢查限制、基本型態不能直接作為型態引數，以及擦除後相同參數型態的過載限制。

Oracle Java Tutorials 頁面標示以 JDK 8 為背景，這裡只取經 JLS 與本機原型核對的基本語言規則，不沿用頁面中的舊式建構寫法，也不把 JLS 版本誤當課堂 JDK 要求。
